# 10002.sl / 10002.map 完整正确地图加载方式与 payload 解密报告
## 1. 关键修正结论
这次已经把 `.sl` 后半段 payload 解开。它不是未知空数据，也不是普通压缩包，而是 **Blowfish/ECB 加密后的 Lua 5.1 bytecode**。
解密后确认：NPC、物件/建筑、技能、道具、地图初始化、触发器、出兵/刷怪、赞助大使相关常量，主要都在这个 Lua 字节码里。
## 2. 文件真实分层
| 层 | 文件/数据 | 作用 |
|---|---|---|
| 外层 | `10002.sl` | LZMA_ALONE 压缩容器 |
| 容器头 | `LuaRDGTM` | 自定义地图包头 |
| 地图显示层 | 内嵌 `.map`，大小 `0xE3261` | 地形、预览图、房间选项文本、阵营/玩家槽 |
| 逻辑层 | 后半段 payload，大小 `0x143483E` | 加密 Lua bytecode，包含角色/物件/触发器/地图逻辑 |
| 加载后缓存 | `map(1).o` | 不是完整地图脚本，只是本次加载后的选项缓存：`g_map_display/g_map_opt` |

容器字段：

```text
Magic              = LuaRDGTM
map_size           = 0x000E3261 = 930,401 bytes
payload_size       = 0x0143483E = 21,186,622 bytes
map_offset         = 0x10
payload_offset     = 0xE3271
```
## 3. payload 正确解密方式
`gpigame.dll` 的 `LuaServer::DecryptMap` / `LuaServer::EncryptMap` 调用 Blowfish 类核心时，传入密钥地址为 `DEFAULT_KEY`，长度是 `0x0c`。所以实际密钥不是 11 字节 `DEFAULT_KEY`，而是 12 字节：

```text
44 45 46 41 55 4C 54 5F 4B 45 59 00
ASCII: DEFAULT_KEY\0
```
解密算法：

```text
Blowfish / ECB / no padding
key = b"DEFAULT_KEY" + b"\x00"
解密长度 = payload_size 向下取 8 字节对齐 = 0x1434838
末尾 6 字节不参与 Blowfish 解密，视为尾部/校验/非块数据。
```
解密后的头部：

```text
1B 4C 75 61 51 00 01 04 04 04 08 00 ...
= Lua 5.1 bytecode header
source = =(luac)
```
## 4. 可复现拆包脚本
我已把脚本放进压缩包：`extract_sl_to_map_and_luao.py`。核心逻辑如下：

```python
raw = Path("10002.sl").read_bytes()
dec = lzma.decompress(raw, format=lzma.FORMAT_ALONE)
assert dec[:8] == b"LuaRDGTM"
map_size = struct.unpack_from("<I", dec, 0x08)[0]
payload_size = struct.unpack_from("<I", dec, 0x0C)[0]
map_data = dec[0x10:0x10 + map_size]
payload_enc = dec[0x10 + map_size:0x10 + map_size + payload_size]
key = b"DEFAULT_KEY" + b"\x00"
n = len(payload_enc) & ~7
payload_dec = Blowfish_ECB_Decrypt(payload_enc[:n], key)
# payload_dec 就是 Lua 5.1 bytecode，可保存为 10002.o
```
## 5. gpigame.dll 的真实加载链路
完整运行链路现在可以确定为：

```text

  ↓

  ↓

  ↓
```

## 9. 正确地图文件落盘方式
结合 `gpigame.dll` 的路径模板，标准落盘结构应为：

```text
map/10002/10002.map   # 从 .sl 里拆出的 map_data
map/10002/10002.o     # payload 解密后的 Lua 5.1 bytecode
```
如果引擎处于源码/debug模式，则可能使用：

```text
map/10002/10002_init.lua
map/10002/10002_run.lua
```

但正常发布态走的是 `.o`。
## 10. map(1).o 的定位
你上传的 `map(1).o` 是 Lua 5.1 bytecode，但内容只有：

```lua
g_map_display = 1
g_map_opt = {...}
```

它不是完整地图逻辑，只是加载后/选项相关缓存。完整逻辑应来自 `.sl` payload 解密出的 `10002.o`。
